## `core` toolset

### `search_series`

Find official BLS/FRED series IDs for a topic and place. Start here.

#### Usage
Call this first whenever you do not already have a series ID, then pass the chosen
`series_id` to `get_latest` (current value) or `get_series` (history).
Covers employment and payrolls (CES), unemployment and labor force (CPS, LAUS for
states), wages and hours, prices (CPI by item and metro), job openings, hires and
quits (JOLTS), employment cost (ECI), productivity, and FRED macro series (GDP,
interest rates, mortgage rates, jobless claims).

#### Tips
- Put the measure in `query` and the place in `geography`.
- Prefer `match: "catalog"` results: curated and validated. `fred_search` results are
  FRED full-text matches; check the title and units before using them.
- Seasonally adjusted (SA) series are best for month-to-month comparisons; NSA for
  comparing the same month across years.

#### Output format
`results` best first, each with series_id, title, units, frequency,
seasonal_adjustment, geography, latest_observation and match. `notes` explains
whether FRED was also searched.

IMPORTANT: Never guess or construct series IDs yourself, because made-up IDs return
wrong or no data. Always take IDs from this tool's results.

#### Parameters

| Parameter | Type | Required | Default | Description |
|---|---|---|---|---|
| `query` | str | yes |  | What to measure, in plain words: 'unemployment rate', 'average hourly earnings manufacturing', 'job openings', 'CPI shelter', 'initial jobless claims', '30-year mortgage rate'. |
| `geography` | str \| null | no | null | Optional place: a state ('Texas'), metro ('Chicago'), or census region ('South'). Omit for national data. |
| `limit` | int | no | 10 |  |

#### Returns

- `query`: str
- `results`: list[object]
- `fred_searched`: bool
- `notes`: list[str]

### `describe_series`

Explain exactly what a series measures: title, units, frequency, coverage and notes.

#### Usage
Use when you need to confirm a series is the right one (definition, units, seasonal
adjustment, date coverage) before quoting it, or to check if it is discontinued.

#### Output format
`meta` (title, units, frequency, seasonal_adjustment, geography, url, notes),
`observation_start` / `observation_end` / `last_updated` when the source provides
them, and `in_catalog` (true = curated and validated by this server).

#### Parameters

| Parameter | Type | Required | Default | Description |
|---|---|---|---|---|
| `series_id` | str | yes |  | A BLS or FRED series ID, e.g. 'LNS14000000' or 'UNRATE'. |

#### Returns

- `meta`: object
- `observation_start`: str \| null
- `observation_end`: str \| null
- `last_updated`: str \| null
- `in_catalog`: bool
- `release`: object \| null

### `find_area`

Turn a place name into an area_id and its local unemployment series IDs.

#### Usage
Call before `get_occupation_wages` or `get_area_employment` (they take `area_id`).
Also the fastest route to local unemployment: take `laus.unemployment_rate` from the
result and pass it to `get_latest` or `get_series`.

#### Tips
- Metros are named by their principal cities ("Austin-Round Rock-San Marcos, TX");
  counties and metros can share names (Austin County, TX vs the Austin metro), so check
  `level`.
- `has_occupation_wages` is false for counties (OEWS does not publish them); use the metro.
- Metro and county unemployment series are not seasonally adjusted: compare with the
  same month a year earlier.

#### Output format
`results` best first: area_id (us, state:48, metro:12420, county:48453), name, level,
has_occupation_wages, has_area_employment, laus (series IDs), score. `notes` flags
ambiguous matches.

IMPORTANT: If `notes` says several places match closely, confirm with the user which one
they mean, because answering for the wrong place is worse than asking.

#### Parameters

| Parameter | Type | Required | Default | Description |
|---|---|---|---|---|
| `query` | str | yes |  | Place name or state abbreviation: 'Texas', 'TX', 'Austin', 'Travis County', 'Chicago', 'United States'. |
| `level` | `national` \| `state` \| `metro` \| `county` \| null | no | null | Restrict to 'national', 'state', 'metro' or 'county'. |
| `limit` | int | no | 8 |  |

#### Returns

- `query`: str
- `results`: list[object]
- `notes`: list[str]

### `get_latest`

Get the most recent published value of each series, with standard comparisons.

#### Usage
Best tool for "what is the current ..." questions. For trends or charts over time,
use `get_series` instead.

#### Tips
- For rates (units in percent) changes are in percentage points and the percent-change
  fields are null on purpose.
- `latest_period` is the latest data the agency has published, which may be one or
  two months behind today; say so when answering.
- For prices, `pct_change_from_year_ago` on an index (e.g. CPI) is the inflation rate.
- Also the best tool for "how has X changed over the past year": the year-ago fields
  give the change for the latest period.
- A null year-ago value means the agency never published that period (e.g. October
  2025). `notes` names it and the nearest published periods.

#### Output format
Per series: `meta` (with citation url), latest_period, latest_value, preliminary,
previous_period/value, change_from_previous, pct_change_from_previous,
year_ago_period/value, change_from_year_ago, pct_change_from_year_ago, change_units,
notes. `failed` lists IDs that returned nothing, with a next step.

IMPORTANT: Quote the period and cite `meta.url` with each number, because readers need
to know which release the figure comes from. If a comparison period was not published,
say so, and never present a neighbouring period's value under its label.

#### Parameters

| Parameter | Type | Required | Default | Description |
|---|---|---|---|---|
| `series_ids` | list[str] | yes |  | 1-20 series IDs from search_series, e.g. ['LNS14000000', 'CPIAUCSL']. |

#### Returns

- `results`: list[object]
- `failed`: list[object]
- `retrieved_at`: str

### `get_series`

Get historical observations for one or more series, optionally transformed.

#### Usage
Use for trends, comparisons over time, and "since <year>" questions. For a single
current value use `get_latest`. Several IDs are fetched in one call; compare series
with the same units and frequency.

#### Tips
- Do the arithmetic here with `transform` instead of computing it yourself.
- Omit `end_date` for current data. Never guess the latest month: it is in
  `latest_available`, and `notes` says when `end_date` cut off newer data.
- A null point means the agency never published that period; `notes` names such gaps.
- Values marked in `preliminary_periods` are subject to revision.

#### Output format
Per series: `meta`, `transform`, `value_units`, `points` ([period, value], oldest
first) or `observations` (detailed), `latest_available`, `returned`, `available`,
`truncated`. `failed` lists IDs that returned nothing; `notes` explains caps,
questionable transforms, unpublished periods and data cut off by `end_date`.

IMPORTANT: If `truncated` is true you are missing older data; narrow `start_date` or
raise `max_points` rather than describing the shortened window as the full history.

#### Parameters

| Parameter | Type | Required | Default | Description |
|---|---|---|---|---|
| `series_ids` | list[str] | yes |  | 1-10 series IDs from search_series. |
| `start_date` | str \| null | no | null | Start: 'YYYY', 'YYYY-MM' or 'YYYY-MM-DD'. Default: 5 years ago. |
| `end_date` | str \| null | no | null | Last period, same formats. Default: latest available. |
| `transform` | `level` \| `pct_change_year_ago` \| `pct_change_prior_period` \| `change_year_ago` \| `change_prior_period` | no | "level" | 'level' = values as published; 'pct_change_year_ago' = % change vs the same period a year earlier (inflation from a price index, wage growth); 'pct_change_prior_period' = % change vs previous period; 'change_year_ago' / 'change_prior_period' = difference in units (use these for rates: percentage points). |
| `max_points` | int | no | 60 | Most recent observations kept per series. |
| `response_format` | `concise` \| `detailed` | no | "concise" | 'concise' = [period, value] pairs (default, fewer tokens); 'detailed' adds dates, per-observation footnotes and source notes. |

#### Returns

- `results`: list[object]
- `failed`: list[object]
- `notes`: list[str]
- `retrieved_at`: str

## `wages` toolset

### `find_occupation`

Find Standard Occupational Classification (SOC) codes for a job title.

#### Usage
Call before `get_occupation_wages`, which takes SOC codes.

#### Tips
- `group` tells you the level: `detailed` is one occupation (Registered Nurses);
  `major` is a whole family (Healthcare Practitioners and Technical Occupations).
  Pick the level the question is about.
- "Tech" or "healthcare" questions usually mean the major group (15-0000, 29-0000).

#### Output format
`results` best first: occupation_code, title, group, score.

#### Parameters

| Parameter | Type | Required | Default | Description |
|---|---|---|---|---|
| `query` | str | yes |  | Job title or field in plain words ('registered nurse', 'software developer', 'truck driver', 'healthcare'), or a SOC code ('29-1141'). |
| `limit` | int | no | 8 |  |

#### Returns

- `query`: str
- `results`: list[object]

### `get_occupation_wages`

Get official employment and wages for occupations by state or metro (BLS OEWS).

#### Usage
- Specific places: `occupation_codes` + `area_ids` (from `find_area`).
- Rankings ("highest-paying metros for nurses"): `occupation_codes` + `rank_across`.
- National only: `occupation_codes` alone.
National figures for the same occupations are always included in `national`, so
comparisons with the U.S. need no extra call.

#### Tips
- Median is the typical worker; mean is pulled up by high earners. Prefer median
  unless asked for average.
- Figures are for May of `reference_period`, the latest OEWS survey; say so (e.g.
  "as of May 2025") rather than "last year" or "currently".
- For trends in pay over time use `search_series` / `get_series` (e.g. average hourly
  earnings); OEWS is a yearly snapshot.

#### Output format
`reference_period`; `rows` (area_id, area_name, occupation_code, occupation,
employment, jobs_per_1000, location_quotient, hourly/annual mean and median, annual
p10/p90, annual_only, top_coded); `national`; `failed`; `notes`; `sources`.

IMPORTANT: Never state a number for a field listed in `top_coded`; say it is at or above
the OEWS reporting cap, because BLS does not publish the exact value.

#### Parameters

| Parameter | Type | Required | Default | Description |
|---|---|---|---|---|
| `occupation_codes` | list[str] | yes |  | 1-5 SOC codes from find_occupation, e.g. ['29-1141']. |
| `area_ids` | list[str] \| null | no | null | Specific places from find_area, e.g. ['state:48', 'metro:12420']. Omit, with no rank_across, for national figures only. |
| `rank_across` | `states` \| `metros` \| null | no | null | Rank every 'states' or 'metros' instead of listing area_ids. |
| `sort_by` | `annual_median` \| `annual_mean` \| `hourly_median` \| `hourly_mean` \| `employment` \| `location_quotient` | no | "annual_median" | Measure used to rank when rank_across is set. |
| `limit` | int | no | 15 | Top areas kept per occupation when ranking. |
| `year` | int \| null | no | null | OEWS May reference year. Omit for the latest published. |
| `response_format` | `concise` \| `detailed` | no | "concise" | 'detailed' adds 25th and 75th percentile annual wages. |

#### Returns

- `reference_period`: str
- `rows`: list[object]
- `national`: list[object]
- `failed`: list[object]
- `notes`: list[str]
- `sources`: list[str]

## `regional` toolset

### `get_area_employment`

Get jobs, establishments and average weekly wages for counties, metros or states.

#### Usage
For local job counts and pay by industry ("how many people work in health care in
Travis County?", "which industries employ the most in Austin?"). Data comes from
QCEW, a near-census of employers; it is the only source here with county detail.
For monthly local unemployment use `find_area` → `laus` series → `get_latest`.

#### Tips
- QCEW lags about 5-6 months; `reference_period` says which quarter you got.
- It is not seasonally adjusted: use the *_year_ago fields for change, not the
  previous quarter.
- `disclosed: false` means BLS suppressed the cell; never treat it as zero.

#### Output format
`reference_period` (e.g. 2026-Q1); `rows` (area, industry, ownership, disclosed,
establishments, employment, avg_weekly_wage, employment_change_year_ago,
employment_pct_change_year_ago, avg_weekly_wage_pct_change_year_ago); `failed`;
`notes`; `sources`.

#### Parameters

| Parameter | Type | Required | Default | Description |
|---|---|---|---|---|
| `area_ids` | list[str] | yes |  | 1-10 places from find_area, e.g. ['county:48453', 'metro:12420']. |
| `industries` | list[`total` \| `private` \| `federal_government` \| `state_government` \| `local_government` \| `goods_producing` \| `service_providing` \| `natural_resources_mining` \| `construction` \| `manufacturing` \| `trade_transportation_utilities` \| `retail_trade` \| `information` \| `financial_activities` \| `professional_business_services` \| `professional_scientific_technical` \| `education_health_services` \| `health_care_social_assistance` \| `leisure_hospitality` \| `accommodation_food_services` \| `other_services`] | no | ["total"] | Industry slices. 'total' = all jobs; 'private'; government by level; or sectors such as 'construction', 'manufacturing', 'health_care_social_assistance', 'leisure_hospitality'. List several for a breakdown. |
| `year` | int \| null | no | null | Calendar year; give with quarter. |
| `quarter` | int \| null | no | null | 1-4; give with year. Omit both for the latest. |

#### Returns

- `reference_period`: str
- `rows`: list[object]
- `failed`: list[object]
- `notes`: list[str]
- `sources`: list[str]

## `compute` toolset

### `real_wage_growth`

Are wages keeping up with inflation? Inflation-adjusted growth of a wage series.

#### Usage
For "real wages", "purchasing power" and "are wages keeping up with prices"
questions. Find the wage series with `search_series` first ("average hourly
earnings manufacturing", "employment cost index wages").

#### Tips
- `latest` gives the year-over-year nominal, inflation and real growth for the most
  recent period; `window` gives the cumulative change since `start_date`. Use
  `start_date` for "since 2019" or "since the pandemic" questions.
- The price index is matched to the wage series' seasonal adjustment and frequency
  automatically; `notes` says what was done.
- Real growth is exact, (1 + wage growth) / (1 + inflation) - 1, so it can differ from
  a simple subtraction by a few hundredths.

#### Output format
`wage`, `deflator` (metadata with citation urls), `frequency`, `base_period`,
`latest` (period, nominal_wage, nominal/inflation/real pct change year ago, real_wage),
`real_wage_rising`, `window` (cumulative changes), `points`, `truncated`, `notes`.

IMPORTANT: Cite both `wage.url` and `deflator.url`, because the answer depends on both
series.

#### Parameters

| Parameter | Type | Required | Default | Description |
|---|---|---|---|---|
| `wage_series_id` | str | yes |  | A wage LEVEL series from search_series: average hourly/weekly earnings (e.g. CES3000000003 manufacturing) or an Employment Cost Index (e.g. CIU2020000000000I). Not a rate or a percent-change series. |
| `deflator` | `cpi_u` \| `cpi_w` \| `pce` | no | "cpi_u" | 'cpi_u' (all urban consumers, the usual choice), 'cpi_w' (urban wage earners, used for Social Security), or 'pce' (the Fed's preferred index). |
| `start_date` | str \| null | no | null | Window start, e.g. '2019' or '2020-02'. |
| `end_date` | str \| null | no | null | Window end. Default: latest. |
| `max_points` | int | no | 60 | Most recent periods in `points`. |

#### Returns

- `wage`: object
- `deflator`: object
- `frequency`: str
- `base_period`: str
- `latest`: object \| null
- `real_wage_rising`: bool \| null
- `window`: object \| null
- `points`: list[object]
- `truncated`: bool
- `notes`: list[str]

### `compare_series`

Rank several series on one measure, optionally against a benchmark such as CPI.

#### Usage
For "which industries/states/groups had the biggest ...", "rank ...", and "compare A,
B and C" questions. Get the IDs from `search_series` (e.g. average hourly earnings for
each industry), then rank them here instead of fetching each and sorting yourself.

#### Tips
- Percent measures compare across different units; level and change measures only
  make sense for series in the same units (`notes` warns otherwise).
- Rates (unemployment, quits) must use change_* measures; percent changes of rates are
  left out with a note.
- `gap_vs_benchmark` > 0 means the series grew faster than the benchmark.

#### Output format
`rows` ranked highest first: meta, rank, value, value_units, latest_period,
latest_value, base_period, base_value, gap_vs_benchmark. `benchmark`, `failed`,
`notes` (comparability warnings).

IMPORTANT: Read `notes` before answering, because they flag series that end in
different periods or are in incomparable units.

#### Parameters

| Parameter | Type | Required | Default | Description |
|---|---|---|---|---|
| `series_ids` | list[str] | yes |  | 2-25 series IDs from search_series to rank against each other. |
| `measure` | `latest_value` \| `change_year_ago` \| `pct_change_year_ago` \| `change_since` \| `pct_change_since` | yes |  | 'latest_value'; 'pct_change_year_ago' / 'change_year_ago' (vs same period a year earlier); 'pct_change_since' / 'change_since' (vs `since`). Use change_* for rates (percentage points). |
| `since` | str \| null | no | null | Required for *_since. 'YYYY' compares with that year's average; 'YYYY-MM' with that month. |
| `benchmark_series_id` | str \| null | no | null | Optional series computed the same way and subtracted from each row, e.g. 'CUSR0000SA0' (CPI) to compare wage growth with inflation. |

#### Returns

- `measure`: `latest_value` \| `change_year_ago` \| `pct_change_year_ago` \| `change_since` \| `pct_change_since`
- `since`: str \| null
- `rows`: list[object]
- `benchmark`: object \| null
- `failed`: list[object]
- `notes`: list[str]

## Resources

Read-only documents a client attaches as context.

### `econ://catalog`

_application/json_

Every series in the gateway's curated, validated catalog (~300 series, ~15K tokens).

Each entry has the series ID to pass to the data tools, its title, category, units,
frequency, seasonal adjustment and geography (omitted for the United States). Prefer
econ://catalog/{category} for one topic, or the search_series tool to find a series by
description.

### `econ://releases`

_application/json_

Last and next release dates of the headline BLS and BEA releases.

Covers the jobs report, CPI, jobless claims, JOLTS, the ECI, state and metro
unemployment, PPI, productivity, personal income (PCE) and GDP. No newer data exists
before a release's next date.

### `econ://methodology`

_text/markdown_

Index of methodology notes: seasonal adjustment, revisions, OEWS, QCEW, LAUS, etc.

### `econ://status`

_application/json_

Gateway version, mounted toolsets, whether API keys are configured, upstream health.

Health covers circuit-breaker state, rate-limit headroom and BLS daily quota use. Key
values are never included.

### `econ://catalog/{category}`

_application/json_

The catalog series in one category: unemployment, wages, inflation, employment, etc.

The body lists every category with its count, so an unknown category is easy to fix.

### `econ://series/{series_id}`

_application/json_

One series: metadata, coverage, release schedule and latest value.

Combines describe_series and get_latest for a single BLS or FRED ID, e.g.
econ://series/LNS14000000 (U.S. unemployment rate).

### `econ://methodology/{topic}`

_text/markdown_

One methodology note, e.g. econ://methodology/rates-and-changes.

## Prompts

Question templates a user picks in their client.

### `occupation_wages`

What an occupation earns in a state or metro area (OEWS), with the U.S. median.

- `occupation` (required): Occupation in plain words, e.g. 'registered nurses'. Provide a value matching the following JSON schema: {"description":"Occupation in plain words, e.g. 'registered nurses'.","type":"string"}. Encode non-string values as JSON.
- `place` (optional): State or metro area, e.g. 'Texas' or 'Austin, TX'. Provide a value matching the following JSON schema: {"description":"State or metro area, e.g. 'Texas' or 'Austin, TX'.","type":"string"}. Encode non-string values as JSON.

### `labor_market_snapshot`

Current state of the labor market: unemployment, jobs, pay, inflation, claims.

- `place` (optional): 'the United States', a state or a metro area. Provide a value matching the following JSON schema: {"description":"'the United States', a state or a metro area.","type":"string"}. Encode non-string values as JSON.

### `local_economy`

Jobs, pay by industry and unemployment for a county, metro area or state (QCEW).

- `place` (required): County, metro area or state, e.g. 'Travis County, TX'. Provide a value matching the following JSON schema: {"description":"County, metro area or state, e.g. 'Travis County, TX'.","type":"string"}. Encode non-string values as JSON.

### `real_wage_check`

Are wages keeping up with inflation? Real wage growth for one pay measure.

- `wage_measure` (optional): Which pay to check, e.g. 'average hourly earnings, private' or 'manufacturing average hourly earnings'. Provide a value matching the following JSON schema: {"description":"Which pay to check, e.g. 'average hourly earnings, private' or 'manufacturing average hourly earnings'.","type":"string"}. Encode non-string values as JSON.
- `deflator` (optional): Price index: cpi_u (usual), cpi_w or pce.
- `since` (optional): Optional start of the window, e.g. '2019' or '2020-02'. Provide a value matching the following JSON schema: {"description":"Optional start of the window, e.g. '2019' or '2020-02'.","type":"string"}. Encode non-string values as JSON.
